# 13.0.0

*2026-11-18*

**Opacity modifiers on zen colours now work.** `zen-bg-zen-muted/40` really
is the muted colour at 40%. It used to come out solid.

It is a major version for one reason, and most apps are not affected: **if
your app generates its own `zen-` classes with zen-ui's UnoCSS preset, and you
wrote a `/NN` on a zen colour, that class now fades as written.** zen-ui's own
components look exactly as they did. Their stylesheets were rebuilt and
compared byte for byte.

## Breaking

**A `/NN` you wrote on a zen colour now fades.** Until now zen colours ignored
the modifier: they are CSS variables, which the stylesheet generator could not
fade, so it dropped the `/40` without a warning and the class rendered solid.
If you wrote one anyway, your page has been showing the solid colour.

To keep the solid look, drop the modifier:

```html
<!-- 12.x: rendered solid. 13.0.0: renders at 40%. -->
<div class="zen-bg-zen-muted/40">

<!-- solid, in both -->
<div class="zen-bg-zen-muted">
```

To find them, search your source for a zen colour followed by a slash, for
example `-zen-[a-z-]*/[0-9]` as a regular expression.

**This only affects apps that run UnoCSS with zen-ui's preset.** If you only
import zen-ui's stylesheet (`@algorisys/zen-ui-react/styles` and the like), you
do not generate any `zen-` classes, and nothing changes for you.

**Your UnoCSS config needs `zenAnimationsPreset`,** next to `zenUnoTheme`:

```ts
import { defineConfig, presetUno } from "unocss";
import { ZEN_PREFIX, zenUnoTheme, zenAnimationsPreset } from "@algorisys/zen-ui-core/uno-preset";

export default defineConfig({
  presets: [presetUno({ prefix: ZEN_PREFIX }), zenAnimationsPreset],
  theme: zenUnoTheme,
});
```

The documented config already has it. Despite its name, that preset is what
keeps a plain colour class like `zen-bg-zen-muted` exactly what it was. With
the theme but not the preset, every plain colour class would switch to
`color-mix()`, and `zen-bg-opacity-*` would start fading zen colours, which it
never did.

## What you get

- **Real translucency with the class you would expect to write.**
  `zen-bg-zen-primary-soft/30` for a faint highlight, `zen-border-zen-border/50`
  for a quieter rule, `zen-ring-zen-primary/50` for a softer ring. It works for
  every zen colour and every utility that takes a colour.
- **Nothing else moves.** Plain colour classes produce exactly the CSS they did
  before, so the only places `color-mix()` appears, and the only places browser
  support for it matters, are classes where you asked for an opacity.

## Fixed

- **Catalogue thumbnails on the demo site** sometimes showed a plain screenshot
  of the page instead of the component. The generator now gives a slow page a
  second chance before falling back.
