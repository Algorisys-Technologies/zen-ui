# 10.4.0

Seven components for assessment platforms — timed tests, coding katas,
spreadsheet exercises, system-design questions and live proctoring. All land in
the **React binding first**; every package bumps to keep one version number, but
they are not in Solid, vanilla or web-components yet.

Nothing was removed, renamed or restyled.

## TimerBadge and TestCountdownBar

```tsx
<TimerBadge deadline={endsAt} onExpire={submit} />
<TestCountdownBar deadline={endsAt} title="Kata 3" actions={<Button>Submit</Button>} />
```

Both take a **deadline**, not a duration they count down. A component that
decrements a number on an interval runs slow in a throttled background tab — the
candidate sees more time than they have, and the server disagrees at submission.
`deadline - now` cannot drift, so a tab that wakes after two minutes asleep shows
the truth immediately.

Four states, escalating at 300s and 60s by default. The last minute pulses as
well as changing colour, because colour alone fails a colour-blind candidate.
`onThreshold` fires once per mark **passed**, comparing two readings rather than
testing for an exact second — a throttled tab skips seconds constantly, and a
5-minute warning that tests for exactly 300 simply never fires.

Neither owns submission. What to submit differs per assessment type.

## CodeEditor and IDEWindow

```tsx
<CodeEditor language="python" value={code} onChange={setCode} onRun={run} />
```

A thin wrapper over `@monaco-editor/react` — an **optional** peer dependency,
lazily imported, so an app that never shows code never downloads it. Deliberately
thin: `options` passes straight through, because re-exporting a curated slice of
Monaco's API only stops you reaching the rest.

What it adds is the consistency every app re-decides: the zen theme rather than a
hardcoded `vs-dark`, a font size that is a prop rather than a magic number, and
read-only. `onRun` is wired to Ctrl/Cmd+Enter. It does **not** execute code —
that is a sandbox, a rate limit and an auth boundary.

`IDEWindow` puts a file list beside it. Switching files remounts the editor, so
Ctrl+Z in one file cannot undo an edit in another.

## SpreadsheetGrid and SheetCalculator

```tsx
<SpreadsheetGrid cells={{ B2: 3, C2: 420, D2: "=B2*C2", D6: "=SUM(D2:D4)" }} />
```

The evaluator is a **recursive-descent parser, not `eval`** — a formula is text a
candidate types, and running it as JavaScript hands them the page. Arithmetic,
A1 references, ranges, and eight functions.

It is honest about its limits. Anything it cannot work out renders as `#NAME?`,
`#VALUE!`, `#DIV/0!` or `#ERROR!` rather than a plausible wrong number, which in
an assessment is the difference between a candidate failing and a candidate being
failed incorrectly. A circular reference is `#CIRCULAR!` — unguarded it is not a
wrong answer, it is a stack overflow that takes the page down.

Aggregates skip text, so a column label sitting inside a range is not an error;
a formula that errors inside a range still propagates.

## ProctorStreamGrid and ProctorFlagOverlay

**It displays; it does not detect.** No webcam is opened, no face is found, no
tab switch is noticed — it takes streams you already have and flags you already
raised. Detection is hundreds of lines tuned to one product's lighting and camera
placement; a design system that shipped it would make every consumer carry a
computer-vision dependency to render a card.

A real responsive grid rather than a wrapping row of fixed-width cards, with an
explicit `max` — a live `<video>` costs a decoder, and a hundred of them is a
browser problem no layout fixes. What it hides, it says it hid.

## ChunkUploader

```tsx
<ChunkUploader file={recording} uploadChunk={send} onComplete={finalise} />
```

`uploadChunk` is yours — a signed URL, a presigned part, a socket. What zen-ui
owns is the arithmetic and the retry policy: chunks tile the file exactly, an
empty file yields **no** chunks, retries are bounded at three, and the backoff
doubles rather than hammering a server that is down. Exhausting the attempts
stops **on** the failed chunk, so Retry resumes from exactly there rather than
skipping a hole into the middle of the file.

## DiagramCanvas and ArchitectureDraw

```tsx
<DiagramCanvas value={xml} onChange={setXml} onSave={persist} />
<DiagramCanvas provider="yappydraw" onChange={setJson} onError={setError} />
```

An embedded editor over `postMessage`. No npm diagram package: a diagram editor
is a whole application, and vendoring one would be the largest dependency in
zen-ui by an order of magnitude to serve one screen.

Two providers. `"drawio"` is diagrams.net, third-party and hosted.
**`"yappydraw"` is Algorisys's own** — client-side, free and self-hostable, which
is the better answer for an exam that must not depend on someone else's uptime.
It is not a URL swap: YappyDraw speaks a structured RPC bridge
(`{__yappy, id, method, args}`) where draw.io emits an event stream, and its
documents are JSON rather than XML.

One thing to know before wiring YappyDraw: it refuses cross-origin control unless
**its** operator allowlists your origin at deploy time — a framing page cannot
opt itself in. Until that is configured the bridge times out, which is what
`onError` reports.

The frame is sandboxed without `allow-same-origin`, so the editor cannot reach
your document.

## RichText — images and maths

```tsx
<RichText value={html} onChange={setHtml} onImageUpload={upload} math />
```

`onImageUpload` returns the URL to embed. Without it Jodit inlines the file as a
base64 data URI, which works and quietly puts a two-megabyte string inside the
HTML you then store and re-read on every page load.

`math` renders `$…$` and `$$…$$` through KaTeX, another optional peer. The editor
holds **TeX source** and the rendering goes in a preview beneath it, because
source is the only form that survives a round trip through storage and back into
an editor. `renderMath` is exported separately so the question, the preview and
the printed report render identically.
