# 10.3.1

One fix. If you are using `Splitter`, take this one.

## Clicking the divider did not focus it, so the keyboard did nothing

Click a splitter's divider, press an arrow, and the **page scrolled** instead of
the divider moving. The keyboard support was all there and all correct — it was
simply unreachable the way anyone actually reaches for it.

The divider suppresses the browser default on pointer-down, to stop a drag
selecting text across both panes. That same default is what moves focus to the
element you clicked. So focus stayed wherever it already was, usually the
document body, and the arrow keys were never the splitter's to claim.

Tabbing to the divider worked fine, which is exactly why this survived being
tested: a keyboard-only test never clicks. It is fixed by moving focus
explicitly on pointer-down, before the drag begins — not on click, because the
arrow key may well be pressed before the pointer is released.

Verified on every divider in the demo, including the three-panel and vertical
cases and a `disabled` splitter, which correctly still does nothing.

No API change. Nothing to migrate.
