# 12.6.0

*2026-11-05*

**A DataTable whose toolbar is one button no longer spends a row on it, and
header styling reaches sortable headers.** Both are in every binding.

Nothing is removed or renamed, and no existing table changes how it looks
unless you set the new prop or the header tokens.

## Put the toolbar's buttons in the pager row

A list with nothing above it but a Columns button gives up about 50px of
height to that one button. Set `toolbarPlacement="pagination"` and the
toolbar's menu buttons (Export, Group by, Columns) move into the pager row,
beside "Rows per page" and the page buttons.

```tsx
<DataTable data={invoices} columns={columns} enablePagination
  enableColumnVisibility toolbarPlacement="pagination" />
```

- The search box, if the table has one, stays above the table, next to what
  it filters.
- A table without a pager keeps its buttons on top, so they never disappear.
- The default is `"top"`: tables that don't set it are unchanged.
- Web components: `<zen-data-table toolbar-placement="pagination">`.
- In vanilla and web components, Export is the only toolbar menu, so Export
  is what moves.

## Fixed: sortable headers ignored the header text style

If you set `--zen-table-head-text-transform` (say, `uppercase`) or
`--zen-table-head-letter-spacing`, plain headers took it but sortable ones
didn't: the browser resets both on buttons, and a sortable header's label is
a button. They follow the tokens now. If you added your own CSS to force
this, you can remove it. With the tokens at their defaults, nothing looks
different.
