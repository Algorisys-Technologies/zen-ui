# 13.3.0

*2026-11-18*

**The four bindings now behave alike.** Every option one binding had and
another lacked has been added where it was missing, a dozen places where
vanilla or web components quietly did less than React and Solid now work the
same, and the demo site has the same pages, at the same addresses, in every
binding.

Nothing breaks: every change adds an option or fixes something that did not
work. A few things look different because they now work. They are listed under
**Behaviour you may notice** below.

## New

- **Solid:** CodeEditor `loading` (what to show while the editor loads), and
  RichText `math` (formulas, rendered with KaTeX) and `onImageUpload`.
- **React:** CodeEditor `loaderConfig`, to serve the editor from your own host
  instead of a CDN. PivotFilterMenu `onSort` and `sortDirection`, to sort from
  the filter menu.
- **Vanilla and web components:** PivotFilterMenu sorting; RichText `math` and
  `onImageUpload`; TreeTable you can control (`expanded`, `sorting`,
  `globalFilter`, `rowSelection` and their change events, plus a class per row).
- **Web components:** `input-id` on `<zen-native-select>`, `<zen-input>` and
  `<zen-checkbox>`, so `<label for="…">` can point at the real control.
- `renderMath` is exported everywhere, so a formula renders the same way in the
  editor and wherever else you show the text.

For `math`, install `katex` and import its stylesheet once:

```ts
import "katex/dist/katex.min.css";
```

## Fixed

- **React: `onImageUpload` never ran.** A dropped or pasted image was not sent
  to your handler. It now is, and the URL you return is what gets embedded.
- **Solid and vanilla: the rich-text editor was missing most of its toolbar.**
  The HTML source view, full screen, alignment, indent, search and pasting
  behaviour were absent, and a pasted image skipped `onImageUpload`. The editor
  now has its full feature set.
- **Vanilla: the rich-text editor showed an empty box** instead of an editor.
- **Date range filters could be cleared only once** (React and Solid), and not
  at all in vanilla. Clear now works every time.
- **Vanilla and web components: a dropdown inside a filter bar** (Combobox or
  Select) reopened right after you picked a value, and then could not be opened
  again.
- **Web components: a popover opened in the top-left corner of the page** when
  its trigger was another zen element.
- **Vanilla: the `style` option did nothing** on cards and the other simple
  components. It is applied now.
- **Vanilla: a column's header class** was dropped once a table scrolled
  virtually.
- **Solid: the tick on the chosen sort direction** sat on the wrong side in
  right-to-left pages.

## Behaviour you may notice

These bring Solid and vanilla in line with what React already does:

- **Solid and vanilla rich-text editors show their full toolbar.** Pasting HTML
  now asks whether to keep it as HTML, as React's editor does.
- **Dropping or pasting an image into a Solid rich-text editor inserts it**,
  inline, unless you pass `onImageUpload`. Before, Solid did not handle image
  drops at all.
- **Solid's code editor says "Loading editor…" while it loads**, where it used
  to show an empty box.
- **React's code editor keeps your `loading` placeholder** until the editor is
  ready, instead of switching to a generic "Loading…" partway through.

## Demo site

- Every binding's demo has the same pages: 18 pages that some bindings lacked
  were added. The one exception is the form-library adapters page, which exists
  only in React and Solid because only they have those adapters.
- Every page has one address, the same in every binding. Old addresses such as
  `/button-new` still work and take you to the new one, so bookmarks keep
  working.
