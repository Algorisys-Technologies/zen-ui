# 12.11.0

*2026-11-16*

**Freeze what matters, style what you need: in Solid first.** This release
lets you freeze rows in a DataTable, give a pivot grand totals, and style
tables and schedules column by column, row by row and cell by cell, without
overriding zen-ui's own classes. It also fixes pinned columns and pivots in
right-to-left pages, totals that scrolled away from their pinned column, and
a Columns menu you could not pin from with the keyboard.

The new options ship in **`@algorisys/zen-ui-solid`** in this release;
React, vanilla and web components get the same props in the next one.
**StatusBar**, which 12.10.0 shipped in Solid, now ships in **React, vanilla
and web components** too (`<zen-status-bar>`).

Nothing breaks. Every new option is off until you set it, and a table, pivot
or schedule that sets none of them draws exactly as before. The fixes change
how things look only where they were wrong (see *Fixed*).

## New: tables

- **Freeze rows.** Pin rows to the top or bottom of a DataTable, and they
  stay in view while the rest scroll. They stay even when a filter or the page
  would hide them, which makes this the place for a "my company" row or a
  benchmark line.

  ```tsx
  <DataTable data={lines} columns={columns} getRowId={(l) => l.id}
    enableRowPinning initialRowPinning={{ top: ["L1"], bottom: ["L60"] }}
    stickyHeader maxBodyHeight={320} />
  ```

  `rowPinning` and `onRowPinningChange` make it controlled. Rows stay in view
  when the body scrolls (`stickyHeader` or `fillHeight`). Row pinning works
  in the plain table body; with virtualization or row ordering it is ignored.
- **A footer that stays in view.** Totals already stuck to the bottom of a
  scrolling table; `stickyFooter` does the same for a footer without totals.
- **Style a column, or one cell.** A column's `meta.className` styles its
  cells. As a function of the row, it styles one cell at a time, for example
  a negative balance in red. `meta.headerClassName` styles its header. Both
  work in DataTable and TreeTable.

  ```tsx
  { accessorKey: "balance", header: "Balance",
    meta: {
      headerClassName: "zen-text-end",
      className: (r) => cn("zen-text-end", r.balance < 0 && "zen-text-zen-error"),
    } }
  ```

- **The body text size is a token.** Set `--zen-table-cell-font-size` and
  `--zen-table-cell-line-height` (they default to the small size the cells
  always used) on the page, or on one table through its new `style` prop.

## New: pivot

- **Grand totals.** `totals={{ row, column, grand }}` adds a totals column,
  pinned to the end edge, and a totals row, pinned to the bottom. Both stay
  in view as you scroll either way. The grid adds nothing up itself, because
  an average's total is not the sum of the averages and your data may be on
  a server. You answer for the totals the way you answer for cells: `columns`
  gives one totals column per value field, and `columnHeader` and `label`
  name them.
- **`height`** sizes the grid without a sized parent. **`class`** and
  **`style`** reach its root.

## New: schedules

- **Row height.** `rowHeight` on Gantt sets every row's height, for example
  48 for a touch screen. On ProductionSchedule it is the least height a row
  gets; a machine that stacks more jobs still gets the room it needs. Every row
  in a chart keeps one height, because that is what keeps the dependency
  arrows on their bars. PlanningCalendar takes `laneHeight`.
- **Chart height.** `maxBodyHeight` replaces the 32rem a Gantt or
  ProductionSchedule scrolls after.
- **Colour a row or a bar.** `rowClassName` tints a task's or a machine's row;
  `barClassName` colours a bar and wins over its status colours. Use it to
  follow one work order across machines, or to show one team's work.
- **The small print is a token.** Subtitles, percentages and axis sub-labels
  read `--zen-schedule-label-font-size` (10px by default).
- **SpreadsheetGrid** takes `cellClassName(ref, value)`, and **Tree** takes
  `itemClassName(node)`.

Not changed, on purpose: the schedules do not start following
`data-density`. An app that already sets `data-density="touch"` would have
seen its charts reflow on upgrade. Use the size props above instead.

## Fixed (Solid; React, vanilla and web components in the next release)

- **Right-to-left pages: pinned columns stuck to the wrong edge.** A column
  pinned "left" now sticks on the start edge, which is the right edge in an
  Arabic or Hebrew page, and its divider shadow faces the scrolling columns.
- **Right-to-left pivots stopped drawing after the first screen.** Scrolling
  sideways in an RTL pivot left the new columns blank, and the frozen row
  labels sat on the left. Both now follow the reading direction.
- **A pinned column's total scrolled away from it.** The footer and totals
  cells of a pinned column are now pinned with it.
- **The checkbox column scrolled away from a pinned name.** When anything is
  pinned left, the selection, drag and expand columns are pinned with it.
  `onColumnPinningChange` still reports only your own columns.
- **You could not pin a column with the keyboard.** The Columns menu's pin
  buttons could not be reached with Tab inside a menu. Each column is now a
  submenu (Show column; Not pinned, Pin to left, Pin to right) that works
  entirely from the keyboard, as it already did in vanilla.
