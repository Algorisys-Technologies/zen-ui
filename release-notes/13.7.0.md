# 13.7.0

*2026-11-25*

**Select and Toast are now written the same way in every binding.** Until now
React's `Select` was built from parts (`SelectTrigger`, `SelectContent`, …)
and its toast took an object, while Solid's `Select` took a list of options and
its toast took a message. Code written for one did not run in the other. Now
every binding accepts the Solid way of writing both. React and vanilla keep
their old forms as well, so nothing you have already written changes.

**Gantt charts can show the actual dates as the main bar.** With
`actualLayout="primary"`, the bar showing when work really ran becomes the main
bar, and the plan becomes a dashed outline beneath it.

Nothing breaks. Every change adds a way of doing something; none removes or
changes one.

## New

- **`<Select options>` in React**, the form the Solid and vanilla bindings
  already take. Pass a list of options and the label, trigger, list and error
  message are drawn for you:

  ```tsx
  <Select
    label="Country"
    placeholder="Choose a country"
    options={[
      { value: "us", label: "United States" },
      { value: "ca", label: "Canada" },
    ]}
    value={country ?? undefined}
    onChange={setCountry}   // the value string, or null
  />
  ```

  - `errorMessage`, `invalid`, `required`, `disabled`, `name`, `defaultOpen`
    and `onOpenChange` work as they do in Solid.
  - An option whose value is the empty string, such as "All", works and can be
    chosen again.
  - `id` goes on the trigger, so `<label htmlFor={id}>` names the control.

  Without `options`, React's `Select` is exactly the Radix root it was, so the
  compound form keeps working.

- **Vanilla's `Select` takes Solid's other props too:** `onChange` (alongside
  `onValueChange`), `required`, `defaultOpen` and `onOpenChange`. In web
  components these are the `required` and `default-open` attributes and the
  `zen-open-change` event.

- **The Solid toast calls work in React, vanilla and web components:**

  ```ts
  toast("Saved");
  toast.success("Profile updated");
  toast.error("Couldn't save");

  const id = toast.loading("Uploading…");   // a spinner; stays until replaced
  toast.success("Uploaded", { id });        // the same toast becomes the result

  toast.promise(save(), { loading: "Saving…", success: "Saved", error: "Couldn't save" });
  toast.dismiss(id);
  ```

  - Reusing an `id` replaces that toast. A finished "Uploaded" toast closes
    after the usual 5 seconds; it does not keep the loading toast's "stay
    open" setting.
  - `<Toaster position="bottom-right">` places the stack, with the same six
    positions as Solid. In web components it is the `position` attribute on
    `<zen-toaster>`.
  - The object form, `toast({ title, description, variant })`, still works in
    React and vanilla.

- **`actualLayout="primary"` on the Gantt**, in every binding. On a task with
  actual dates, the actual bar becomes the main bar: it shows the status
  colour and the percentage, it is what you click, and dependency arrows
  attach to it. The plan is drawn as a slim dashed outline beneath it. A task
  with no actual dates is drawn as usual. In web components it is the
  `actual-layout="primary"` attribute.
