# 12.15.1

*2026-11-17*

**Nothing you can see changes.** This release removes a misleading kind of
class from zen-ui's own source, and documents the trap behind it for apps
that write their own `zen-` classes.

## Fixed

- **Opacity modifiers on zen colours never did anything.** A class like
  `zen-bg-zen-muted/40` reads as "muted at 40%", but it renders the solid
  colour, exactly like `zen-bg-zen-muted`. Every zen colour is a CSS variable,
  and the stylesheet generator cannot fade a colour it cannot see inside, so
  it drops the `/40` without a warning.

  zen-ui's components carried about 145 of these, in every binding. They
  have always rendered solid, so they were rewritten to the plain class they
  were already drawing. We compared the colours of every element on every
  demo page, in all four bindings, before and after: nothing moved.

  **If your app generates its own `zen-` classes** with zen-ui's UnoCSS
  preset, the same is true there: `/40` on a zen colour is ignored. For real
  translucency, mix the colour yourself:

  ```html
  <!-- before: renders solid, whatever it says -->
  <div class="zen-bg-zen-muted/40">

  <!-- after: genuinely 40% -->
  <div class="zen-bg-[color-mix(in_srgb,var(--zen-color-muted)_40%,transparent)]">
  ```

  Making `/40` work in the preset was not done on purpose. It would turn
  every one of those classes translucent at once, in zen-ui and in your app,
  which is a visible change and would need a major version.
