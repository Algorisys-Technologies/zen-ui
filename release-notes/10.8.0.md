# 10.8.0

Four new components, a table that keeps its state in the URL, and a TreeTable
that can finally open.

Nothing was renamed, removed or restyled. Every change here is additive except
the TreeTable fix, which restores behaviour that never worked — so if you are
on 10.7.x, upgrading needs no code changes.

## TreeTable could not expand at all

If you used `<TreeTable>` in React or Solid without `enablePagination`, the
tree could not open. Not by clicking a chevron, not with the keyboard, and not
via `defaultExpanded`. Every root row rendered, every chevron was there, and
nothing happened when you used one.

It was invisible from the outside because nothing errored — the chevrons are
drawn from the data, which was fine; only the row model was short. If you
worked around this by turning pagination on, you can turn it back off.

```tsx
// Both of these now work. Previously only the second one did.
<TreeTable data={accounts} columns={columns} />
<TreeTable data={accounts} columns={columns} enablePagination />
```

Paging is unchanged: a page still holds whole root rows, and expanding one
keeps its children with it rather than pushing the next root onto page 2.

The vanilla and web-components bindings were never affected.

## UrlDataTable — the querystring layer, once

A `DataTable` whose entire state lives in the URL. Sort, filters, search and
page are read from `params` and written back through `onParamsChange`, so a
link to a filtered, sorted, third page is just the URL — bookmarkable, shareable,
and survivable across a refresh.

It owns no state and imports no router, so Remix's `useSearchParams`, Next,
TanStack Router and plain `history.pushState` all wire in the same way:

```tsx
const [params, setParams] = useSearchParams();

<UrlDataTable
  params={params}
  onParamsChange={setParams}
  rows={data.rows}
  columns={columns}
  page={data.page}
  pageCount={data.pageCount}
  pageSize={20}
/>
```

The wire format is meant to be read by humans, because these URLs get pasted
into tickets:

```
?sort=name:asc,createdAt:desc&filters=status:active&search=acme&page=2
```

Multi-column sort is ordered — the order in the URL is the precedence the server
should apply. A filter value may itself contain a colon; only the first one
separates key from value. Half-written pairs are dropped rather than guessed, so
a truncated URL loses a column instead of silently sorting by nothing and
handing back a differently-ordered page than the one asked for.

Any mutation resets to page 1, except a page change. Without that, filtering
while on page 7 of 7 asks the server for page 7 of a result set that now has
two pages, and you get an empty table.

## NativeSelect — the platform control, styled

zen-ui had one select, the Radix listbox, and nothing for the case it is wrong
for. A field whose options are plain text does not need a JS-driven popup: the
platform `<select>` submits inside a plain `<form>` with no hidden input, opens
as the OS picker on a phone — a wheel on iOS, a sheet on Android — and costs
nothing to render for a long list.

```tsx
<NativeSelect value={country} onChange={(e) => setCountry(e.target.value)}>
  <option value="">Choose a country…</option>
  <optgroup label="Europe">
    <option value="fr">France</option>
  </optgroup>
</NativeSelect>
```

It carries `Input`'s class list, so the two line up in a form — measured at the
same 40px height and the same border colour. `optgroup` and disabled options
work as they always have.

There is deliberately no `size` prop: on a `<select>`, `size` is the number of
visible rows, and redefining it as a height would break anyone already passing
it. It also does not grey itself while an empty placeholder option is selected —
style that yourself if you want it.

In vanilla and web-components, options are data rather than slotted children,
matching every other list family in those bindings.

## Label and Collapsible

Two primitives that existed in no binding, and that everyone was open-coding —
a bare `<label class="zen-text-sm zen-font-medium">` for the first, and a
single-item Accordion for the second, which drags in a value prop, a heading and
an item wrapper to wrap a region that has nothing to coordinate with.

```tsx
<Label for="email" required>Email</Label>

<Collapsible defaultOpen>
  <CollapsibleTrigger>Advanced options</CollapsibleTrigger>
  <CollapsibleContent>…</CollapsibleContent>
</Collapsible>
```

One divergence worth knowing, because it is real rather than an oversight: in
React, a `<Label>` next to a disabled Checkbox dims by itself. In Solid it does
not — Kobalte nests the control in a wrapper, so the label is never its sibling
and a `<div>` never matches `:disabled`. Pass `disabled` to the label
explicitly; that works identically in all four bindings.

## Combobox rows can be more than a line of text

`Combobox` and `MultiCombobox` rendered `option.label` and nothing else, and
`label` is a `string` — so a row could only ever be one line of plain text.
Anything richer meant reaching for a different library.

`content` is that row:

```tsx
<Combobox
  options={[
    {
      value: "ada",
      label: "Ada Lovelace",
      content: (
        <div>
          <div>Ada Lovelace</div>
          <div class="zen-text-xs zen-text-zen-muted-fg">Engineering · 9 years</div>
        </div>
      ),
    },
  ]}
/>
```

`label` keeps every job it already had — it is what filtering matches, what the
trigger shows once a value is picked, what `creatable` compares against for
"already exists", and what a MultiCombobox chip renders. That is why `content`
is a second field rather than a widened `label`.

It is data rather than a render prop, so it ports: React and Solid take a node,
vanilla and web-components take a DOM `Node`.

## DataTable: column footers, and server-owned filtering

**Footers.** TanStack has carried `footer` on every `ColumnDef` since v8 and
DataTable rendered none of them, so a column total had nowhere to go — the one
thing a financial table always needs. Declare `footer` on any column and the
table grows a `<tfoot>`; columns without one render an empty cell so the row
stays aligned. Tables that declare no footers are untouched.

In vanilla the shape is `footer?: (rows) => Child`, matching how that binding's
`DataTableColumn` already diverges — it is data-driven and has no column objects
to hand back.

**Filter operators can be turned off.** New `enableFilterOperators`, defaulting
to `true`, so nothing changes unless you ask. Turn it off when the server owns
the predicate: the operator select is a client-side matcher, so against a
server-filtered table it offered a choice nothing acted on.

It also fixes two visible consequences. With operators on, a filter value is
`{ op, value }` — pick an operator before typing and the active-filter chip read
`Question: [object Object]`. And the URL carried an operator the loader never
honoured. `UrlDataTable` sets this off for you.

Sort arrows went from 12px to 14px, and the unsorted hint from 30% to 60%
opacity — at 12px and 30% it was invisible on a header unless you knew to look.

## Also

- `UrlDataTable` keeps the filter operator in the URL and debounces typing, so
  a keystroke no longer costs a request.
- Renderable cell values pass through instead of being coerced, so a status
  pill or a link in a cell no longer renders as `[object Object]`.
- `UrlDataTable` owns its toolbar row rather than letting DataTable draw a
  second search box beside its own.
