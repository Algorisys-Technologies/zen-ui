# 10.7.0

**Every component now exists in every binding.** The vanilla and web-components
bindings gain the fifteen components React and Solid already had, and with that
`check:parity` reports no component living in only one binding — in any
direction, for the first time.

Nothing was removed, renamed or restyled.

## What arrived

If you build with `@algorisys/zen-ui-vanilla` or
`@algorisys/zen-ui-web-components`, these are new to you and are the same
components, not lookalikes:

**For assessment and exam software** — `TimerBadge` and `TestCountdownBar`
(a clock computed from a deadline, so a throttled background tab cannot hand a
candidate extra time), `CodeEditor` and `IDEWindow` over Monaco,
`SpreadsheetGrid` and `SheetCalculator` with a real formula evaluator,
`ProctorStreamGrid` and `ProctorFlagOverlay`, `ChunkUploader`, `DiagramCanvas`
and `ArchitectureDraw`.

**For documents and layout** — `DocumentViewer` (images directly, PDFs to a
canvas through `pdfjs-dist`), `DiffView` (what changed between two snapshots of a
record), `Splitter` (resizable panes), and `SortableList` (reorder by dragging or
entirely by keyboard). `Timeline` items can now be collapsible and carry the
payload that changed.

## They behave the same, not merely look the same

The parts of these that can be wrong are one shared implementation in
`@algorisys/zen-ui-core`, pinned by assertions every binding runs: the diff, the
document and zoom maths, the reorder reducer, the splitter geometry, the
countdown, the chunk plan, and the formula evaluator. A binding owns only its
DOM.

That is why the two bugs found in React's spreadsheet could not reappear
elsewhere, and why the keyboard reordering announces the same words and cancels
the same way in all four.

## Two things to know if you use the factories or the elements

**Vanilla and web-components are data-driven where React composes children.**
React registers `<SplitterPanel>` and `<SortableListItem>` through a context;
without a framework there is none, so the panes and rows are data:

```js
Splitter({
  defaultSizes: [30, 70],
  panels: [
    { min: 20, collapsible: true, content: manuscript },
    { min: 30, content: preview },
  ],
});
```

The dividers and grab handles are implied — n panels can only ever have n-1
dividers. This is the same decision every other data-driven family here already
follows.

**A `<zen-*>` attribute that defaults to true is spelled as a value, not a flag.**
An absent boolean attribute in HTML cannot mean "unset", so
`handle`, `sticky`, `toolbar`, `changed-only`, `auto-start`, `show-progress`,
`line-numbers` and `reset-on-src-change` take `"false"` explicitly:

```html
<zen-sortable-list handle="false" items="…"></zen-sortable-list>
<zen-document-viewer src="…" toolbar="false"></zen-document-viewer>
```

Every callback is also a `CustomEvent`, so a page with no script at all still
works:

```html
<zen-spreadsheet-grid rows="9" cols="5"
  cells='{"B2":3,"C2":420,"D2":"=B2*C2","D6":"=SUM(D2:D4)"}'>
</zen-spreadsheet-grid>
```

## Fixed

**`<zen-input-otp>` rendered nothing, and took the page with it.** The element
declared `style` as a property, which replaced the element's own `style` with one
that was undefined — so it threw while connecting, once per OTP field on the
page. If you use `InputOTP` in the web-components binding, it works now.

**`<zen-diagram-canvas>` and `<zen-document-viewer>` needed their optional peers
declared.** `pdfjs-dist` and `@monaco-editor/loader` are now listed as optional
peer dependencies of the vanilla and web-components packages, so your installer
knows about them instead of relying on a hoisted copy from somewhere else.

## New optional peer dependencies

Only needed for the components that use them; nothing else changes if you skip
them.

```
npm i pdfjs-dist              # DocumentViewer, for PDFs only
npm i @monaco-editor/loader   # CodeEditor / IDEWindow
```

PDFs also need a worker path, because only your bundler knows where its copy
landed:

```js
import workerSrc from "pdfjs-dist/build/pdf.worker.min.mjs?url";
DocumentViewer({ src: pdfUrl, workerSrc });
```
