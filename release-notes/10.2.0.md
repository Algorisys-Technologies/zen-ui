# 10.2.0

Two new components for audited backoffice apps — showing a scanned document,
and showing what changed in a record — plus a small addition to Timeline that
makes a long history readable.

**These land in the Solid binding first.** React, vanilla and web-components
still ship 10.2.0 so every package keeps one version number, but `DiffView` and
`DocumentViewer` are not in them yet, and `Timeline`'s new props are Solid-only
for now. If you are on React today, this release changes nothing for you. The
ports are the next piece of work; the API below is what they will mirror.

Nothing was removed, renamed or restyled. Existing code keeps working.

## DocumentViewer — put a scanned invoice on screen

zen-ui could already get a document IN — `FileUpload`, `Camera`, `QRScanner`,
`UploadCollection`. It had nothing for looking at one. Every app that needed a
preview hand-rolled an `<img>`, an `<iframe>` and a zoom control.

```tsx
import { DocumentViewer } from "@algorisys/zen-ui-solid";

<DocumentViewer src={signedUrl} name="invoice-8842.pdf" />
```

Images and PDFs, one component. Zoom, fit, rotate, page navigation and a page
count, with a toolbar you can turn off for a thumbnail-sized preview.

**It does not fetch.** `src` is a URL you already have the right to read or a
`Blob` you already hold — no `method`, no headers, no retry policy, the same
rule `UploadCollection` follows. A signed URL works untouched: the query string
is stripped before the extension is read, which is the step that, when skipped,
renders every document in an app as a broken image.

**PDFs draw to a canvas, not an `<iframe>`.** An iframe hands the browser's own
viewer a frame box and lets it lay out inside, so the page count is unreadable,
rotation is impossible, and zoom crops instead of magnifying unless you inflate
the frame by `1/zoom` and scale it back — a workaround that behaves differently
in every engine. Drawing the page ourselves makes zoom a render parameter and
rotation a number. The canvas is drawn at device pixel ratio, so a 2× display
shows the document rather than a blur of it.

PDF support needs `pdfjs-dist`, an **optional** peer dependency loaded only when
a PDF actually appears. If you only ever show images, you never install it and
never download it. When you do, pdf.js needs a worker and will not start without
one, so pass its URL — only your bundler knows where its copy landed:

```tsx
import workerSrc from "pdfjs-dist/build/pdf.worker.min.mjs?url";  // Vite

<DocumentViewer src={pdfUrl} workerSrc={workerSrc} />
```

If your app already sets `GlobalWorkerOptions.workerSrc` once at startup, leave
the prop off and that is used. Forget both and you get a message naming the fix,
rather than pdf.js's own error about a global you never set.

**Zoom, page and rotation are controlled-or-uncontrolled, per knob.** Leave them
alone and the component owns them. Pass `zoom` with `onZoomChange` and you do —
which is what lets a window-level `+` / `-` / `0` shortcut drive the viewer, a
normal expectation of a document viewer and impossible against a purely
uncontrolled one. `minZoom`, `maxZoom` and `zoomStep` set the range, and the
buttons disable at the bounds rather than going quietly dead.

Switching documents in place resets zoom, page and rotation, because opening the
next scan still held at 400% from the last one is never what was meant. Pass
`resetOnSrcChange={false}` if you disagree. A knob you control is never reset —
the component does not fight a value you own.

A file it cannot draw falls through to a plain card with a download button
instead of an empty box. `onDownload` is presence-gated, like
`UploadCollection`'s delete button: no handler, no button, because a
dead-looking control costs the user a click to discover.

## DiffView — what changed between two snapshots

For an audit payload, a revision, or a form's dirty state.

```tsx
<DiffView
  before={{ status: "pending",  amount: 1200, currency: "EUR" }}
  after={{  status: "approved", amount: 1250, currency: "EUR" }}
/>
// two rows: status and amount. currency is identical, so it is not shown.
```

**It takes what your audit column actually holds.** A real one is `nvarchar`,
not JSON: a row carries a serialised object for one action, a bare array for
another, an ad-hoc map for a third, a line of prose someone typed for a fourth,
and an empty string when there was no before at all. A plain `JSON.parse` throws
on three of those and takes the panel down with it.

```tsx
<DiffView before={log.old_value} after={log.new_value} />   // unparsed, as stored
```

Strings are parsed by a parse that never throws. Empty means absence, so a
creation shows "not set" on the before side alone rather than reading as "no
changes". Text that is not JSON stays the text it is. Two objects get the field
table; anything else — an array, prose, a number — is shown whole, side by side,
because it has no field names to put in the left column and forcing it into a
table would misrepresent it. Override with `parse` if your column is not JSON.

Unchanged fields drop out by default, because an audit entry is about what
changed. Pass `changedOnly={false}` for the whole record — right for a
side-by-side review screen, wrong for a history feed.

It gets the cases a quick diff gets wrong. **`null` is a value and absence is
not**: clearing a field to `null` is a change, a field that is simply gone is a
removal, and the two render differently. Object key order is not a change, but
array order is. Two equal `Date`s are equal. `NaN` equals itself, so a field
that was unparseable in both snapshots does not report a phantom edit.

Kind is never signalled by colour alone — a replaced value is struck through and
an absent one is a dash with a screen-reader label — so the diff still reads in
greyscale and to someone who is colour-blind.

`keys` selects and orders the fields, `labels` renames them for display, and
`format` decides how a value is drawn:

```tsx
<DiffView
  before={before}
  after={after}
  keys={["amount", "status"]}
  labels={{ amount: "Amount (EUR)" }}
  format={(value, key) => (key === "amount" ? `€${value}` : String(value))}
/>
```

Keys are printed verbatim when you give no label. Turning `weight_kg` into
"Weight kg" would be guessing at your wording, and it is the same reason
`Timeline` takes a formatted timestamp string rather than a `Date`.

## Timeline — collapsible item bodies

A history where every entry carries a payload is unreadable fully expanded; the
events stop being scannable, which is the one thing a timeline is for.

```tsx
{
  id: "e1",
  title: "Approved",
  timestamp: "09:14",
  collapsible: true,
  defaultOpen: false,
  collapseLabel: "Payload",        // defaults to "Details"
  children: <DiffView before={before} after={after} density="compact" />,
}
```

It is a native `<details>`, so it is keyboard-operable and the browser's in-page
search still finds text inside a collapsed row — which matters, because an audit
trail is exactly where someone reaches for Ctrl+F.

Pass `open` with `onOpenChange` and the caller owns which rows are open — the
only way to build a single-open accordion, where opening one row closes the
others. `collapseLabel` also takes a function of the open state, for a toggle
that reads "Show" and "Hide" rather than one fixed word.

All of these are optional. A `Timeline` you already have renders exactly as it
did.

## Putting the three together

The combination is the point. An audit panel is a `Timeline` of events, each
carrying a `DiffView` of the payload that changed, next to a `DocumentViewer`
showing the document the change was made against.

```tsx
<Timeline
  items={log.map((e) => ({
    id: e.id,
    title: e.action,
    description: e.actor,
    timestamp: e.at,
    state: STATE_BY_ACTION[e.action],
    collapsible: true,
    children: <DiffView before={e.before} after={e.after} density="compact" />,
  }))}
/>
```

`Timeline` already carried the timestamp, the semantic colour per event and the
day grouping. The mapping from your action names to a colour stays yours — a
component library cannot know an app's action vocabulary, and guessing at it is
worse than asking.
