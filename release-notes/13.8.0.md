# 13.8.0

*2026-11-25*

**Gantt milestones show the date they were actually reached.** Give a
milestone the date it was really hit, and a small diamond marks that date
beneath the planned one. A sign-off that was planned for the 12th and
happened on the 15th now shows both.

Nothing breaks. A milestone without an actual date looks exactly as it did in
13.7.

## New

- **An actual date on a Gantt milestone**, in every binding. A milestone is a
  single moment, so its actual date is one too: `actualEnd`, or `actualStart`
  if that is the only one you give.

  ```ts
  { id: "signoff", name: "Design sign-off", milestone: true, start: jul12, actualEnd: jul15 }
  ```

  - **A smaller diamond marks the date it was reached**, beneath the planned
    diamond, in the status colour. The planned diamond stays where it was, so
    dependency arrows still meet its points.
  - **A reached milestone counts as Complete**, and the variance column shows
    how late or early it was ("+3d"). A milestone whose date has passed with
    no actual date is still shown as Delayed.
  - **With `actualLayout="primary"`** the reached diamond is the main one,
    which the arrows attach to, and the plan is a hollow diamond beneath.
  - **A screen reader hears both dates**, for example "Milestone,
    12 Jul 2026, Complete, actual 15 Jul 2026".
  - `actualBarColor` and `actualBarClassName` style the marker as they do the
    actual bar.

  In web components, put `"actualEnd"` on the milestone in the `tasks` JSON as
  an ISO date.

## Demo site

- The Gantt page's **Planned vs actual** section has two milestones in every
  chart: a design sign-off reached three days late, and a launch still ahead.
