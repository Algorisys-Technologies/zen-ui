# 12.7.0

*2026-11-06*

**The vanilla and web-components DataTable can now do everything the React
and Solid one can.** Until this release, a table built with
`@algorisys/zen-ui-vanilla` or `<zen-data-table>` had sorting, paging,
selection, editing and server export, but none of the column and data tools:
no hiding or moving columns, no per-column filters, no grouping, no expanding
rows. All of them are here now, with the same names and behaviour as in React
and Solid.

Nothing is removed or renamed, and every new feature is off until you turn it
on. One fix changes what a screen reader hears: see "Fixed" below.

If you use React or Solid, nothing in this release changes your tables.

## DataTable in vanilla and web components

Each feature is a flag, as in React and Solid. For web components the
attribute is the same name in kebab-case (`enable-column-visibility`), data
goes in as a property, and changes arrive as `zen-…-change` events.

- **Manage columns.** `enableColumnVisibility` adds a Columns menu: show and
  hide columns, Reset columns. `enableColumnOrdering` lets people drag a
  header sideways, or, in the menu, press Alt+↑ / Alt+↓ on a column.
  `enableColumnResizing` puts a handle on each header's edge: drag it, or Tab
  to it and use the arrow keys. `enableColumnPinning` with
  `initialColumnPinning: { left: ["name"], right: ["total"] }` freezes
  columns while the table scrolls sideways.
- **Remember the layout.** `persistKey: "invoices"` keeps order, widths,
  hidden columns and pins across reloads. The saved layout is the same one
  React and Solid write, so a page that moves to another binding keeps it.
- **Filter each column.** `enablePerColumnFilters` adds a row of filters under
  the header, chosen per column with `meta.filterVariant`: text and number
  (with an operator: contains, starts with, ≥, …), a range, a list, or yes /
  no. Active filters show as chips above the table; remove one, or Clear all.

  ```ts
  DataTable({ data, enablePerColumnFilters: true, columns: [
    { accessorKey: "name", header: "Name" },
    { accessorKey: "status", header: "Status",
      meta: { filterVariant: "select", filterOptions: [{ label: "Paid", value: "paid" }] } },
    { accessorKey: "total", header: "Total", meta: { filterVariant: "numberRange" } },
  ] });
  ```

- **Let the server filter and sort.** `manualFiltering` and `manualSorting`
  take `data` as already filtered and sorted and report every change
  (`onColumnFiltersChange`, `onSortingChange`) for you to re-fetch. Turn the
  operators off with `enableFilterOperators: false` when your server only
  does "contains".
- **Expand a row.** `renderSubRow: ({ row }) => details(row)` adds a toggle
  that opens a full-width detail row underneath. It works in paged tables and
  in `enableRowVirtualization`.
- **Group rows.** `enableGrouping` with `initialGrouping: ["status"]` nests
  rows under "Paid (12)" group rows that open and close; columns with
  `meta.aggregate: "sum"` show each group's subtotal. A Group by menu changes
  the grouping; group by two columns to nest.
- **Export and act on a selection.** `enableExport` adds an Export menu that
  downloads the filtered rows as CSV or JSON (`exportOnlySelected` for just
  the selected ones). `renderBulkActions` shows a bar while rows are
  selected, with your buttons and "Select all N matching".
- **Fewer rows spent on the toolbar.** `toolbarPlacement: "pagination"`
  moves all of these menus into the pager row.

## Fixed

- **Vanilla and web components: a Select or NumberField given an
  `aria-label` was announced without a name.** The label landed on the
  wrapper around the control instead of the control itself, so a screen
  reader read "combobox" or "spin button" and nothing more. It is on the
  control now, as in React and Solid. If you worked around it by labelling
  the inner element yourself, you can stop.
