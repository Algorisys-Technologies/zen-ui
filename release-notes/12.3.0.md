# 12.3.0

*2026-11-05*

**Everything 12.2.0 shipped in Solid is now in React, vanilla and web
components.** 12.2.0 made zen-ui fit for desktop ERP screens, but most of it
reached the Solid binding only. This release brings the rest of the bindings
level: the same components, the same props, and the same words, translatable
in the same way. Whichever binding you use, the 12.2.0 notes now describe your
package too.

Nothing is removed or renamed, and nothing you have to opt into changes how an
existing page looks. Two places now draw a state that your page already
declared but that went unshown, listed first below. We checked everything else
by recording what a screen reader gets on every demo page of every binding
before and after, and comparing them.

## Two things that may look different

Both are bugs: the page already asked for this, and Solid already did it.

- **A field marked `aria-invalid="true"` now draws the red error border**
  (React and vanilla Input, React's Select trigger), the same border an
  explicit `invalid` gives. Forms that report errors that way, React's
  `BoundField` and `FormControl` among them, now show which field is wrong
  instead of only telling a screen reader. If you drew your own error border
  for this, you can drop it.
- **Sidebar menu buttons take the theme's text colour** (React and vanilla).
  Without the optional `/preflight` stylesheet, a row rendered as a `<button>`
  used the browser's default button colour (black), which was close to
  invisible in the dark theme.

## The 12.2.0 features, now in every binding

If you use React, vanilla or web components, all of these are new to you. The
[12.2.0 notes](12.2.0.md) explain each one.

- **Translate every built-in word.** Wrap the app in `LocaleProvider` (web
  components: `<zen-locale-provider>`) and pass `messages` for any of zen-ui's
  strings; what you leave out stays English. Plurals follow each language's
  rules, and the same provider sets the locale and currency numbers use.

  ```tsx
  <LocaleProvider locale="hi-IN" messages={{ "common.close": "बंद करें" }}>
    <App />
  </LocaleProvider>
  ```

  In vanilla, pass `children` as a function, so the components it builds read
  the provider when they are created:

  ```ts
  LocaleProvider({ locale: "hi-IN", messages: hindi, children: () => [Toolbar(), DataTable(table)] });
  ```

  In web components, the elements inside `<zen-locale-provider>` use its words,
  and redraw when you change its `messages` property.
- **New components:** AmountField and QuantityField, keyboard shortcuts
  (Kbd, ShortcutProvider, useShortcut, a `?` help overlay), ContextMenu,
  DocumentTabs, Tile and TileGrid, QRCode and Barcode, DateInput, TreeSelect,
  LookupField, FilterBuilder and ViewManager.
- **DataTable:** totals and subtotals, server-side export, keyboard row
  navigation and a right-click menu in every binding, and in every binding
  inline editing, spreadsheet-style cell navigation with copy and paste, and
  virtualized rows for tens of thousands of records. One gap remains in
  vanilla and web components: their table has no grouping, per-column filters
  or expandable rows yet.

  Server export sends your backend the same request for the same table in all
  four bindings, so one export endpoint serves them all.
- **Additions to existing components:** ObjectNumber formats a raw `number`
  in a locale and currency; Sidebar can collapse to icons or hide, and becomes
  an overlay below a width you choose; ShellBar takes a `search`; StatCard has
  `size="lg"` and a `chart`; Combobox and Select take `invalid`; the Calendar
  is fully keyboard-driven (vanilla's was not) and mirrors its arrow keys in a
  right-to-left page.

## Fixed

- **StatCard figures were 8px too tall in 12.2.0** (Solid). Adding `size`
  dropped the figure's tight line height, so every existing StatCard grew.
  They are back to their 12.1 height.
- **Vanilla and web components leaked memory in about 25 components**
  (Combobox, TreeSelect and every other component that opens and closes a
  panel): every opening after the first left document listeners behind. This had been the case since 7.0.0.
- **Vanilla Select ignored every pick after it was first closed.**
- **Web components: some elements nested inside others rendered empty**,
  for example `<zen-alert-title>` inside `<zen-alert>` and
  `<zen-avatar-fallback>` inside `<zen-avatar>`.
- **React DataTable:** picking a value in an inline select editor did not save
  it, and a per-column filter on a column with no `filterVariant` matched
  nothing.
- **React MultiCombobox showed raw values as chips** (an option's value, not
  its label) when it first appeared, until something else redrew it.
- **React and vanilla, without the optional preflight:** Breadcrumb, Stepper
  and FileUpload showed browser list bullets and indents, and a StatCard used
  as a link was underlined.
- **Solid: words in 18 places could not be translated** despite 12.2.0's
  claim that every word could, including Carousel's arrows, Link's "(opens in
  a new tab)" and Map's "Loading map…". They are in the catalogue now.

## Bundle size

Translation has a cost. Every component that shows a built-in word carries the
English defaults for all of them, about 9 kB gzipped once per app, however
many components you use. A React page that uses Gantt now weighs 66 kB
gzipped where it was 56 kB. A single Button is unchanged at about 18 kB. A
later release will split the defaults so each component carries only its own
words.
