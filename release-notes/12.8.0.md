# 12.8.0

*2026-11-06*

**DataTable columns with a width now keep it when the table can pin or
resize columns.** Until this release, a column's `size` was only a
suggestion: when the columns did not fit, the browser squeezed every one of
them to fit the screen. In a table with pinned columns that meant there was
nothing to scroll past, so pinning did nothing: at 1100px wide, a Name column
sized 180px was drawn at 86px and the table never scrolled. A column you
resized wider than the room left was squeezed straight back.

Nothing is removed or renamed. Tables without pinning or resizing look exactly
as they did.

## Fixed

- **Pinned and resizable tables keep their column widths.** In a table with
  `enableColumnPinning` or `enableColumnResizing`, a column with a `size`, a
  column someone resized, and a pinned column are now never narrower than
  that width. When they do not fit, the table scrolls sideways inside its own
  box, and the pinned columns stay put while the rest scroll under them.
  Columns without a `size` still size themselves.

  This changes how those tables look on narrow screens: where they used to
  squeeze, they now scroll. If you would rather keep the old behaviour, turn
  it off:

  ```ts
  <DataTable enableColumnPinning respectColumnSizes={false} … />
  ```

  Every binding, the same in each: React, Solid, vanilla, and
  `<zen-data-table respect-column-sizes="false">`.

## New

- **`respectColumnSizes` for any table.** The same guarantee for a table
  without pinning or resizing: give your columns a `size`, set
  `respectColumnSizes`, and they keep it, with the table scrolling sideways
  when the screen is too narrow.

  ```ts
  DataTable({ data, respectColumnSizes: true, columns: [
    { accessorKey: "name", header: "Name", size: 180 },
    { accessorKey: "email", header: "Email", size: 240 },
  ] });
  ```

  On `<zen-data-table>` it is the `respect-column-sizes` attribute
  (`"true"` or `"false"`; leave it out for the default).
