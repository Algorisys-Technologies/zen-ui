# 10.4.1

Two fixes to `DiagramCanvas`. If you are embedding **YappyDraw**, take this one —
it did not work at all in 10.4.0.

## The embedded editor could not load its own assets

The frame was sandboxed without `allow-same-origin`, so it got an **opaque
origin**. Every asset it then fetched from its own server counted as
cross-origin and needed CORS headers most apps do not send. Measured against
`yappydraw.com`: the document loaded, then all four of its own bundles were
blocked, leaving a blank frame — and nothing the component could detect, because
a cross-origin frame's failures are invisible to the host page.

draw.io survived the omission only because diagrams.net serves its assets with
CORS. That is why the bug shipped: the provider it was written against masked it.

`allow-same-origin` is now in the default sandbox, and there is a `sandbox` prop
if you want to narrow it.

**What that grants, precisely:** the frame gets its own origin back — its
cookies, its storage. It does **not** let the frame reach your document; the
same-origin policy between two different origins does that, and the sandbox was
never what was holding that line.

**The one arrangement to avoid** is a same-origin `src` together with
`allow-same-origin` and `allow-scripts` — a frame on your own origin can then
reach in and remove its own sandbox attribute. Host the editor on a different
origin, which is the normal arrangement anyway.

## The bridge probed before the frame had navigated

A fresh iframe holds an initial `about:blank` that inherits the parent's origin,
so the first `postMessage` was rejected:

```
The target origin provided ('https://www.yappydraw.com') does not
match the recipient window's origin ('http://localhost:5170').
```

The probe loop retried past it and eventually connected, so the integration
worked — but every attempt logged, and a console full of origin errors reads as
broken. It now waits for the frame's `load` event.

Verified: framing `yappydraw.com` goes from **8 console errors to 0**. The only
message left is YappyDraw's own analytics noting it is running in a frame, which
is itself proof its scripts now load.

No API change beyond the new optional `sandbox` prop.
