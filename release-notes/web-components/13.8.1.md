# zen-ui-web-components 13.8.1

*2026-11-26*

**The elements work in a bundled app — and labelled controls are announced
by their label.** If you import this package through Vite, Rollup or webpack,
upgrade: in 13.8.0 the bundler dropped the whole package and no `<zen-*>`
element was ever defined.

Nothing breaks. No attribute, default or visual output changed. This binding is
not on npm yet — install the tarball from `dist-pkg/` as before.

zen-ui is in **beta / internal testing**: pin an exact version.

## Fixed

- **`import "@algorisys/zen-ui-web-components"` defined no elements in a
  bundled app.** The package told bundlers its code had no side effects, so the
  import that registers every element was removed: the bundle came out at a few
  hundred bytes and every `<zen-*>` tag rendered as an empty unknown element. A
  plain `<script type="module">` and the demo site were never affected. Fixed —
  every element is defined after the import, in any bundler.
- **`aria-label` / `aria-labelledby` now reach the control** on
  `<zen-checkbox>`, `<zen-switch>`, `<zen-radio-group>`,
  `<zen-radio-group-item>` and `<zen-slider>`. They stayed on the element
  itself, which is a layout-free wrapper, so the checkbox, radio or slider
  inside was announced without a name:

  ```html
  <zen-checkbox aria-label="Select invoice 1042"></zen-checkbox>
  <zen-slider aria-label="Volume" value="[30]"></zen-slider>
  ```

## Known limitation

Removing an `aria-*` attribute after the element has rendered does not clear it
from the inner control. Set a new value instead.

## Versions are per binding now

Each zen-ui binding carries its own version from here on. Solid is the binding
in production and ships first; React, vanilla and Web Components follow. All
four started from 13.8.0, so the numbers stay comparable — a binding a few
releases behind Solid's is simply waiting for its port. Check the version you
installed before reaching for something in another binding's notes.
