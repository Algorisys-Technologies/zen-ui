# 10.5.0

The seven assessment components from 10.4.0 are now in the **Solid** binding too.

If you are on Solid, everything React got last release is available to you:
`TimerBadge`, `TestCountdownBar`, `CodeEditor`, `IDEWindow`, `SpreadsheetGrid`,
`SheetCalculator`, `ProctorStreamGrid`, `ProctorFlagOverlay`, `ChunkUploader`,
`DiagramCanvas` and `ArchitectureDraw` — same props, same behaviour.

Nothing was removed, renamed or restyled.

## Same API, and same behaviour

Parity here is not "the props match". The logic these components run is the
identical code: the countdown maths, the chunk plan and the formula evaluator
all live in `@algorisys/zen-ui-core` and are pinned by 143 shared assertions. The
bindings only own DOM.

That is why the two bugs found in the React grid could not come back in Solid —
they were fixed in the port rather than rediscovered. Verified in a browser:
identical arithmetic (3 × 420 = €1,260, SUM = €2,095, +21% VAT = €2,534.95), a
cell that holds **96×25** through an edit, and `=1+2*3` typed into a cell
returning **7** rather than `#ERROR!`.

## One real difference, and why

`CodeEditor` loads Monaco through **`@monaco-editor/loader`** — the
framework-agnostic package that `@monaco-editor/react` itself uses. Solid cannot
use the React wrapper, and importing `monaco-editor`'s ESM build directly turned
out not to work: its own worker entry fails to resolve under Vite ("Failed to
resolve module specifier `../../../base/common/worker/webWorkerBootstrap.js`"),
and that is not fixable from inside a component.

Using the same loader as React means both bindings fetch the same Monaco the
same way, so they behave the same rather than merely looking the same — which is
the point of parity. It also removes the worker problem entirely, because the
build it fetches has its workers already wired.

```
npm i @monaco-editor/loader   # optional peer dependency, Solid binding
```

By default it fetches from a CDN. Point it at a copy you host — the answer for an
exam that must not depend on someone else's uptime:

```tsx
<CodeEditor loaderConfig={{ paths: { vs: "/vendor/monaco/vs" } }} />
```

## Where parity stands

`check:parity` reports the React↔Solid direction for React-only components as
**clean** — the 31 names that existed only in React are now in both.

Still open, and next:

- **Solid-only**: `DocumentViewer`, `DiffView`, `Splitter`, `SortableList` and
  their parts need porting to React.
- **vanilla and web-components** have neither set yet.
