# zen-ui 10.0.0

*2026-07-30*

Two things changed, and neither is a component. zen-ui now has a licence, and it
can now actually be installed — which, it turns out, it could not.

No component API changed. No component renders differently. If you are already
using zen-ui and you are not a commercial user, upgrading changes nothing about
your UI; read the first section anyway, because it changes the terms you are
using it under.

## Breaking

**zen-ui now has a licence, and it is noncommercial.**

Until this release there was no `LICENSE` file and no `license` field in any
package. That is not permissive — under copyright the default is *all rights
reserved*, so strictly nobody had permission to use, copy or redistribute any of
it. That was an oversight, not a policy.

It is now [PolyForm Noncommercial
1.0.0](https://polyformproject.org/licenses/noncommercial/1.0.0) (SPDX
`PolyForm-Noncommercial-1.0.0`), copyright Algorisys Technologies Pvt. Ltd.

**Free, and you need to ask nobody:** personal and hobby projects, learning,
experiments, research, and use by schools, universities, registered charities,
public research organisations and government institutions — the licence names
all of these explicitly, whatever their funding.

**Needs a licence first:** anything commercial. That includes internal tools at
a for-profit company, client work, and a free product that exists to support a
paid one. "We do not sell it" is not the same as noncommercial. It is a short
email and the answer is usually yes — see
[COMMERCIAL.md](https://github.com/Algorisys-Technologies/zen-ui/blob/main/COMMERCIAL.md).

What the licence does **not** restrict: reading the code, forking it, modifying
it, or redistributing your changes for any permitted purpose. Your own project
does not have to be free or open. Whatever fair-use rights you have in law are
untouched — the licence says so in as many words.

**If you read "MIT-style internal use" on the project page, that was wrong.**
The landing page carried that line and it has been corrected. MIT permits
commercial use; this licence grants none. If you adopted zen-ui on the strength
of it, get in touch rather than assume the worst — that is exactly the case the
commercial licence exists for.

**zen-ui is source-available, not open source**, and the distinction is worth
being exact about. The Open Source Definition forbids restricting the field of
use, so a noncommercial condition disqualifies a licence from being open source
however public the source is. Please do not describe zen-ui as open source in a
post, a talk, or a dependency list.

## Fixed: the package was not installable

This is the one that has been quietly costing people time.

Every binding declared `@algorisys/zen-ui-core` as a `workspace:*` dependency.
That protocol only resolves inside the zen-ui monorepo, so **every** way of
getting the package from outside it failed:

```
npm install ./algorisys-zen-ui-react-9.10.0.tgz
  npm error EUNSUPPORTEDPROTOCOL  Unsupported URL Type "workspace:": workspace:*

bun add ./algorisys-zen-ui-react-9.10.0.tgz
  error: @algorisys/zen-ui-core@workspace:* failed to resolve
```

Tarball, `file:`, GitHub Packages, a git URL — all of them, for the same reason.
And `zen-ui-core` is a private package, so the range could never have pointed at
anything installable either.

It hid because inside the monorepo it resolves perfectly: the demos, the builds,
the lint and every check were green throughout. The declaration was simply
wrong — no binding externalises core, so it is inlined into the bundle at build
time and the shipped `dist/index.js` imports nothing from it. It is a build-time
dependency and it now says so.

Measured after the fix:

| How you install it | npm | bun |
|---|---|---|
| tarball from `npm pack` | works | works |
| `file:` a package directory | works | fails — bun installs a directory dep's `devDependencies` |
| bundler alias straight at `dist` | works | works |
| the repo in your own `workspaces` | works | works |
| git URL to a subdirectory | unsupported | unsupported |

The last row is not fixable from here: neither installer supports a subdirectory
in a git dependency. Use a tarball or an alias. The
[README's distribution section](https://github.com/Algorisys-Technologies/zen-ui#distribution--sharing-this-library-with-other-projects)
now documents each route, including the bundler-alias setup for a submodule or a
sibling checkout, which was the one people were already using and the one that
was never written down.

## Fixed: TypeScript actually resolves now

The same problem lived in the type declarations. Every `.d.ts` referred to
`@algorisys/zen-ui-core/*`, which a consumer does not have — 37 unresolved
imports, 69 errors, on a strict `tsconfig`. It was masked by `skipLibCheck:
true`, which suppresses errors *inside* declaration files and which nearly
everyone sets.

Core's declarations are now vendored into each package and referenced relatively,
so the published types stand on their own. A consumer with `skipLibCheck: false`
now reports **zero** errors against zen-ui.

If you set `skipLibCheck: true` only to silence zen-ui, you can drop it. You may
still want it for other reasons — `@kobalte/core` ships 27 errors of its own in
its declarations, which is nobody's fault but Kobalte's.

## Smaller packages

`dist/assets/` had been publishing stale demo bundles — output from before the
demo build moved to its own directory, kept alive by a build setting and shipped
because the package includes all of `dist`. Unpacked size:

| | before | after |
|---|---|---|
| `@algorisys/zen-ui-react` | 9.92 MB | **6.36 MB** |
| `@algorisys/zen-ui-vanilla` | 5.82 MB | **4.13 MB** |
| `@algorisys/zen-ui-web-components` | 5.28 MB | **3.54 MB** |

`@algorisys/zen-ui-solid` was already clean. Nothing you import changed; 36% of
the React package was simply not library code.

## Two new dependencies, one fewer

Each binding now depends on `clsx` and `class-variance-authority`. Both are tiny
and already inside the bundle — they are declared because the *published types*
reference `ClassValue` and `VariantProps`, so a consumer needs them present for
the declarations to resolve.

`@algorisys/zen-ui-core` is no longer a dependency of any binding. You never had
to install it and now you are not asked to.

## Demos

The demo footers say what the licence is, which they did not. And the demo
footer's copyright line had been invisible for some time — the sidebar is
sticky, taller than its row, and painted over the first 240px of it, so the line
read as starting mid-word. Both fixed in all four demos.
