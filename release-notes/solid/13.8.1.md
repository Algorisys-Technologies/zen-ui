# zen-ui-solid 13.8.1

*2026-11-26*

**On npm, and labelled controls are announced by their label.** Install with
`npm i @algorisys/zen-ui-solid`. And a Checkbox, Switch, RadioGroupItem or
Slider you name with `aria-label` is now announced by that name — before, a
screen reader read it as an unnamed control.

Nothing breaks. No prop, default or visual output changed.

## New

- **Install from npm.**

  ```bash
  npm i @algorisys/zen-ui-solid solid-js
  ```

  The tarball URL keeps working (it is the same file npm serves), so you do
  not have to switch.

zen-ui is in **beta / internal testing**: pin an exact version.

## Fixed

- **`aria-label` and `aria-labelledby` now name the control a screen reader
  announces**, on Checkbox, Switch, RadioGroupItem and Slider. They landed on
  a wrapper around the control, so the control itself had no name: every
  aria-labelled row-selection checkbox in a table was read as just
  "checkbox". Nothing to change in your code — the labels you already pass now
  work:

  ```tsx
  <Checkbox aria-label={`Select ${row.name}`} />
  <Slider aria-label="Volume" defaultValue={[30]} />
  ```

  A visible `label`, `aria-labelledby` and `<label for>` keep working as
  before. A range slider's thumbs share the name; each still announces its own
  value.

## Versions are per binding now

Each zen-ui binding carries its own version from here on. Solid is the binding
in production and ships first; React, vanilla and Web Components follow. All
four started from 13.8.0, so the numbers stay comparable — a binding a few
releases behind Solid's is simply waiting for its port. Check the version you
installed before reaching for something in another binding's notes.
