# 10.6.0

The mirror image of 10.5.0. Four components that existed only in **Solid** are
now in **React** as well: `DocumentViewer`, `DiffView`, `Splitter` and
`SortableList` — plus the collapsible Timeline entry they were built for.

Nothing was removed, renamed or restyled.

## What they are for

**`DocumentViewer`** shows a scanned document — the other half of `FileUpload`
and `Camera`. Images render directly; PDFs render to a canvas through
`pdfjs-dist`, an optional peer dependency loaded only when a PDF actually
appears, so an app that never shows one pays nothing.

```tsx
import workerSrc from "pdfjs-dist/build/pdf.worker.min.mjs?url";

<DocumentViewer src={signedUrl} name="invoice-8842.pdf" workerSrc={workerSrc} />
```

A PDF goes to a canvas rather than an `<iframe>` on purpose. Handed a frame box,
the browser's own viewer lays out inside it: the page count is unreadable,
rotation is impossible, and zoom crops instead of magnifying unless you inflate
the frame by 1/zoom and scale it back — which behaves differently in all three
engines. Rendering the page yourself makes zoom a render parameter and rotation
a number. The canvas is drawn at device resolution, so a 2× display shows the
document instead of a blur of it.

Signed URLs work untouched: the query string is stripped before the extension is
read. Skipping that step is what renders every document in an app as a broken
image.

**`DiffView`** shows what changed between two snapshots of the same record — an
audit payload, a revision, a form's dirty state. Unchanged keys drop out, because
an audit entry is about what changed.

```tsx
<DiffView before={log.old_value} after={log.new_value} />
```

Pass the raw column values. A real audit table is `nvarchar`, not JSON: one row
holds a serialised object, the next a bare array, the next a line of prose
someone typed, and an empty string where there was no before at all. A plain
`JSON.parse` takes the panel down on three of those. Strings are parsed with a
parse that never throws, empty means absence, and text that is not JSON stays
the text it is.

It also distinguishes three things a naive diff collapses into one: a field set
to `null` was **cleared** by someone and renders as the literal word; a field
that is simply **gone** renders as a dash labelled "not set" for a screen
reader; and a field that is **new** is marked as added. Kind is never signalled
by colour alone — the replaced value is struck through, so the diff still reads
in greyscale.

**`Splitter`** gives you the editor-shaped layout every writing, diffing or
preview tool wants.

```tsx
<Splitter defaultSizes={[30, 70]}>
  <SplitterPanel min={20}><Manuscript /></SplitterPanel>
  <SplitterHandle />
  <SplitterPanel min={30}><Preview /></SplitterPanel>
</Splitter>
```

Sizes are percentages, so the layout survives a window resize instead of needing
the resize observer every consumer otherwise writes. It writes to no storage of
its own: `onSizesCommit` fires once on release — that is what to persist — while
`onSizesChange` fires during the drag, batched to one animation frame.

**`SortableList`** is a list whose order the user can change, by dragging or
entirely by keyboard.

```tsx
<SortableList items={ids} onReorder={setIds}>
  {ids.map((id) => (
    <SortableListItem key={id} id={id}>
      <SortableListHandle />
      <ChapterRow id={id} />
    </SortableListItem>
  ))}
</SortableList>
```

`items` is always controlled. There is deliberately no uncontrolled mode: a
sortable list holding its own order is one that silently disagrees with the array
you rendered from, and the bug shows up as a row snapping back a second after
the drop.

## The keyboard is not an afterthought in either of them

Both are fully operable without a mouse, and both were verified that way in a
browser rather than asserted.

`Splitter` is a real WAI-ARIA window splitter. Tab to the divider — or click it,
which also focuses it — and it announces itself as a separator controlling the
preceding panel, with `aria-valuenow` as that panel's percentage and
`aria-valuemin`/`max` as its **real** clamps rather than a flat 0–100. Arrow
moves 1%, Shift+Arrow 10%, and Home and End land exactly on the announced
bounds. The divider is drawn as a 1px line with a 12px hit area, so it is
findable with a pointer without being a visual slab.

`SortableList`: Tab to a handle, Space or Enter to pick up, arrows to move,
Space to drop, Escape to put it back exactly where it started. Every pick-up,
move, drop and cancel goes to a polite live region — a drag nobody announces is
invisible. An arrow or an Escape with **nothing picked up** is not claimed, so a
sortable list inside a dialog does not stop the dialog closing.

## Timeline entries can now hold a payload

An audit trail is a `Timeline` of events, each carrying what changed. Set
`collapsible` on an item and put the detail in its `children`, and the events
stay scannable while the detail is one click away.

```tsx
<Timeline items={log.map((e) => ({
  id: e.id,
  title: e.action,
  timestamp: e.at,
  collapsible: true,
  open: openId === e.id,
  onOpenChange: (o) => setOpenId(o ? e.id : null),
  children: <DiffView before={e.before} after={e.after} density="compact" />,
}))} />
```

Existing `Timeline` usage is untouched — an item without `collapsible` renders
exactly as it did.

## The behaviour is shared, not re-implemented

The parts of these four that can be wrong live in `@algorisys/zen-ui-core` and
are pinned by 215 assertions the bindings share: the diff (51), the document
kind and zoom maths (45), the reorder reducer (51) and the splitter geometry
(68). React and Solid own only DOM.

That is deliberate for `SortableList` in particular. Pointer dragging comes from
dnd-kit, but keyboard reordering does **not** — dnd-kit's `KeyboardSensor` is
unused here. `@thisbeyond/solid-dnd` ships no keyboard handling at all and the
other two bindings have no drag library, so three of four need one written by
hand regardless. Taking the free one in React would have left it with different
cancel semantics and different announcement timing from the rest — the kind of
divergence a props-only parity check cannot see.

## Where parity stands

React and Solid are now clean in **both** directions. `vanilla` and
`web-components` have neither this set nor the seven assessment components from
10.4.0; those are next.
