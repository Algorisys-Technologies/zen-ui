# 12.1.0

Three additions, in every binding. Nothing that worked before renders
differently: each one is opt-in, and with none of them set your pages look
exactly as they did in 12.0.1.

## An object page can be the page's h1

`ObjectPageLayout` always rendered its title as an `h2`, its sections as `h3`
and its sub-sections as `h4`. That is right when the object page sits inside a
page that already has its own `h1`, and wrong when the object page *is* the
page, which is the usual case for a document screen. There the page had no `h1`
at all, and moving the title out to an `h1` of your own left the outline jumping
from `h1` to `h3`.

`headingLevel` sets the title's level. Sections sit one level below it and
sub-sections two below, so the outline never skips:

```tsx
<ObjectPageLayout title="SO-4711" sections={sections} headingLevel={1} />
// h1 SO-4711 → h2 per section → h3 per sub-section
```

On the custom element it is the `heading-level` attribute. The default is 2, so
a layout that does not pass it renders the same `h2` / `h3` / `h4` as before.

## A revealed password hides itself again

`PasswordInput` takes `autoHideMs`: once someone reveals the password, it
re-masks itself after that many milliseconds. A password shown to check a typo
no longer stays on screen in plain text when the user walks away. Each reveal
restarts the countdown, and hiding it by hand or unmounting the field clears the
timer.

```tsx
<PasswordInput autoHideMs={10_000} />
```

`auto-hide-ms` on `<zen-password-input>`. Leave it unset to keep today's
behaviour (revealed until toggled back).

## A fifth theme: blue

`data-theme="blue"` (or `applyTheme("blue")`) is an indigo-blue primary
(`#4F46E5`) on cool slate surfaces, with 6 / 8 / 12px corners and an
Inter-first type stack. It is in `THEMES`, so every theme switcher built on that
list offers it. Its success colour is one step darker than the palette it came
from (`#047857`, 5.5:1 against white), because the original green was 3.8:1 and
failed as text.
