# 13.4.0

*2026-11-18*

**Gantt charts can show milestones.** A sign-off, a code freeze or a go-live
is a moment, not a stretch of work. Mark a task `milestone: true` and it is
drawn as a diamond on its date instead of a bar.

Nothing breaks. Tasks without the flag look and behave exactly as before.

## New

- **`milestone` on a Gantt task**, in every binding. The diamond sits on the
  task's `start`, or on its `end` if that is the only date it has. A duration
  or second date given alongside is ignored, so a milestone stays a single point.

  ```ts
  const plan = [
    { id: "build", name: "Build", start: jul13, end: jul24 },
    { id: "freeze", name: "Code freeze", milestone: true, start: jul24 },
  ];
  ```

  - **It is coloured by status, like a bar.** It shows complete once it reaches
    100%, late once its date has passed and it is not complete, and not started
    before that.
  - **Dependency arrows meet the diamond's points**, so a finish-to-start chain
    reads from the work into the milestone and on to the next stage.
  - **A parent task's dates include its milestones**, and clicking a milestone
    calls `onTaskClick` as a bar does.
  - **A screen reader announces it as a milestone with its date and status**,
    for example "Milestone, 10 Jul 2026, Complete".
  - **`barClassName` applies to the diamond as well.**

  In web components, put `"milestone": true` on the task in the `tasks` JSON.

  A task with only a start date and no flag is still not a milestone. It is
  treated as incomplete data, as before, so plans you already have do not
  suddenly sprout diamonds.
