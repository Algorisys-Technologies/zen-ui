# 13.6.0

*2026-11-25*

**Gantt charts can show the plan and what actually happened.** Give a task the
dates its work really started and finished, and a second bar shows them under
the planned one. You can see at a glance what started late, what ran over, and
what never started at all.

The Gantt can also be styled as a project board: text on the bars, the
progress shown on the actual bar, statuses of your own in their own colours, a
legend, and the month shown in weeks.

Nothing breaks. Every one of these is opt-in. A chart that uses none of them
looks and behaves exactly as it did in 13.5.

## New

- **Planned vs actual on a Gantt task**, in every binding. A task's `start` and
  `end` stay the plan. Add `actualStart` when the work really begins and
  `actualEnd` when it really finishes.

  ```ts
  const plan = [
    // Finished, three days late
    { id: "design", name: "Design", start: jul6, end: jul12, actualStart: jul7, actualEnd: jul15 },
    // Running now
    { id: "build", name: "Build", start: jul13, end: jul28, actualStart: jul16 },
    // Planned, not started: only the planned bar
    { id: "qa", name: "QA", start: jul27, end: jul31 },
  ];
  ```

  - **Work in progress runs to today.** A task with `actualStart` and no
    `actualEnd` gets an actual bar that ends at now, with a square end to show
    that it has not finished.
  - **A task that has not started has no actual bar.** If its planned dates
    pass with no `actualStart`, the gap is easy to see.
  - **A parent task rolls up its children.** Its actual bar runs from the first
    child's start to the last child's finish, and it counts as running until
    every child is done.
  - **By default the actual dates also set the status and the slip.** A task
    with an `actualEnd` and no percentage is Complete. A running task is On
    track until its planned end passes, then Delayed. Without a `baselineEnd`,
    the variance column shows how many days the actual finish is past the
    planned end ("+3d"), or how many days today is past it for late work that
    is still running. An explicit `status`, `percentComplete` or `baselineEnd`
    still wins. Set `deriveFromActuals={false}` to draw the bar and change
    nothing else.
  - **A screen reader hears the actual dates with the planned ones**, for
    example "6 Jul 2026 to 12 Jul 2026, Complete, actual 7 Jul 2026 to
    15 Jul 2026".
  - **`actualLayout`**: `"strip"`, the default, keeps the planned bar exactly
    where it was and draws a slim actual bar beneath it. Dependency arrows are
    unchanged. `"split"` draws two bars of equal weight, the plan above.
  - **`actualBarColor`** and **`actualBarClassName`** restyle the actual bar per
    task, as `barAccent` and `barClassName` do the planned one.

  In web components, put `"actualStart"` and `"actualEnd"` on the task in the
  `tasks` JSON as ISO dates, as you do `"start"` and `"end"`. The layout is the
  `actual-layout` attribute. `deriveFromActuals` and the colour and class
  functions are properties.

- **Text on the bars.** `barLabel` and `actualBarLabel` take a function that
  returns the text for each task, such as "Planned (16–20 Nov)" or
  "Actual (24–30 Nov) – 50%". The text goes inside the bar when it fits and
  beside it when it does not, on whichever side has room. Inside a bar it sits
  on a light background, so it stays readable whatever colour the bar is.

- **`progressOn="actual"`** moves the percentage fill, and the status colour
  with it, onto the actual bar. The planned bar becomes a plain grey reference.
  A task with no actual dates keeps its fill on the planned bar.

- **Statuses of your own.** `statusColor` gives a row a CSS colour that
  replaces the built-in four on its status chip and its bars. Pair it with
  `statusLabel` to name it:

  ```ts
  <Gantt
    tasks={tasks}
    statusColor={(t) => t.onHold && "var(--zen-color-accent-purple)"}
  />
  ```

- **A legend.** `legend` set to `true` builds one from the chart, one entry for
  each status label and colour on screen. An array of `{ label, color }` draws
  exactly the entries you give. It sits on its own line under the toolbar.

- **The month in weeks.** `monthColumns="week"` shows the Month view as
  calendar weeks ("2–8", "9–15") instead of days, which leaves room for a label
  on every bar. Other views are unchanged.

- **A subtitle can have more than one line.** Pass a list, such as
  `["Planned: 16-11-2026 → 20-11-2026", "Actual: 24-11-2026 → …"]`, and give
  the rows room with `rowHeight`.
